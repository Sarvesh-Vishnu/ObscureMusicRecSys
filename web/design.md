# Obscure — design contract

Obscure is the web face of ObscureMusicRecSys: pick a song you know and see a **route** of five steps
to a song almost nobody plays, each step a move real ListenBrainz listeners made. A second view, the Lab,
shows the benchmark behind it. Readers: hiring managers and engineers judging recommender-system work.

**The one idea:** the route is drawn on a listeners axis, so a visitor *sees* it descend from the head
into the long tail, and every step carries its evidence (how many people made that move, how the
sound changed, whether someone made it again after the cutoff). One device carries it: the amber line.

## 1. Theme and atmosphere
- **Night line.** A player at night: near-black ground, warm ink. Rules out light mode and warm paper.
- **Evidence-first.** Every number is computed from the exported data; nothing typed. Rules out
  decorative stats, count-ups, invented axes.
- **Quiet.** One accent, hairlines, no cards, no glow, nothing loops.

## 2. Colour and roles
| Token | Value | Role |
|---|---|---|
| `--ground` | `#0d0e10` | page |
| `--raise` | `#15171a` | player bar, art placeholder, search field |
| `--tail` | `#111316` | long-tail zone in the route figure |
| `--rule` / `--rule-2` | `#26292e` / `#3a3e45` | hairlines / control borders |
| `--ink` | `#ece8e1` | primary text (15.8:1 on ground) |
| `--ink-2` | `#b4aea5` | secondary text (8.8:1) |
| `--ink-3` | `#8a857d` | labels, axes (5.3:1 ground, 4.9:1 raise: AA) |
| `--accent` | `#f0a63a` | **the route, and only the route** (9.4:1) |

Amber means "route": the route line and stops, the selected step number, "Play the route", the
highlighted series in a Lab figure (the thing that figure is about). Nothing else is amber.
Dark only, by design (Night line). Palette validator: accent vs neutral passes CVD separation
(ΔE 17.6) and contrast; its lightness/chroma checks fail because the neutral is meant to read as
grey (a highlight encoding, not a categorical palette).

## 3. Typography
- Instrument Sans Variable (display and body; weights 400/500/600) and JetBrains Mono Variable
  (labels, axes, figures, numbers). Self-hosted via @fontsource; no Google requests.
- Scale: 11–12.5 mono labels · 14 small · 16 body · 17–18 lede · 18 side heads · 24–32 chapter heads ·
  32–58 page heads (clamp).
- Tabular numerals wherever numbers sit in columns. Measure ≤ 62ch.

## 4. Components
- **Route figure** (`RouteFigure.tsx`): x = step, y = listeners (log). Dashed head/tail threshold
  (from the export, not typed), tinted tail zone, amber line, stops (seed = ink, end = amber fill).
  Tweens 320 ms on dial change; instant with reduced motion. Drawn at the container's pixel width
  so text keeps its size on phones. Accessible name lists every stop; the tracklist is the
  keyboard/screen-reader equivalent.
- **Dials**: two radio groups as pill segments (λ smoothness, γ pull), three stops each, matching
  the precomputed grid exactly. Never a continuous slider: the routes are not interpolated.
- **Tracklist**: number, art (or empty frame), title/artist button that expands the evidence,
  listeners + head/tail, play (or MusicBrainz link when no preview). Evidence is a definition list.
- **Player bar**: appears on first play. Art, title, position in queue, prev/play/next, Apple credit
  link, 2 px amber progress.
- **Lab figures** (`charts.tsx`): scatter with CI crosshairs, bars with CIs. Direct labels, hover
  and focus tooltips, "Show as table" under each.

## 5. Layout
- Max 1160, gutter 16 / 32. Route view: 7fr main (head, figure, tracklist) + 4fr side (dials,
  standard recommender, seed picker) at ≥ 1024; stacked below in that reading order.
- Lab: chapters as 4fr prose + 7fr figure at ≥ 1024; stacked below.

## 6. Depth
Rules and tone only. No shadows.

## 7. Do and don't
- Do round only the controls (buttons, segments, search): the one nod to a music player.
  Everything else is square. (`tells-ok: big-radius` in styles.css.)
- Don't type a number into copy. Sentences quoting numbers are built in `format.ts` or from
  `lab.json`; claims of "tied" or "no measurable cost" are worded from whether a paired 95% interval
  spans zero.
- Don't add a second accent, a light theme, or a gradient.
- Don't present the app's pull (closeness to the seed) as the benchmark's γ (closeness to a listener).

## 8. Responsive behaviour
- < 520 px: figure height 250, artist tag truncates at 18 chars, tracklist hides the listeners column
  (still in the evidence), evidence aligns full-width.
- Checked at 320, 375 and 1280: no horizontal scroll.

## 9. Notes for an agent
- Data: `public/data/{routes,tracks,lab}.json` are generated by `scripts/export_web.py` and
  `scripts/fetch_previews.py` (repo root). Don't edit by hand. Don't run the export while
  fetch_previews is running (it rewrites tracks.json at the end).
- `npm run dev` (port 5192), `npm test` (vitest: checks the exported routes keep the benchmark's
  rules), `npm run build`. Design scan: `node ~/.claude/skills/munnetrum-design/scripts/tells.mjs web`.

## 10. Amendments

### 10.1 — First build (2026-11-17)
Night line direction, two views (Route, Lab), iTunes previews, name "Obscure" (all chosen by the user).

**Considered and rejected.** Liner-notes (light, tracklist-as-footnotes) and Lab-bench (graph
inspector) directions; one long page; links-only audio; running beam search in the browser (the
subgraph a beam can touch is unbounded for continuous dials, so the dials snap to a precomputed grid
computed by the benchmarked code instead).

**Landing seed.** Chosen by a rule, not by hand: among songs with 500+ listeners whose default
route ends in the long tail, the steadiest descent, then most steps repeated after the cutoff.

**Lead artist.** The benchmark keys artists by credit, so "Korn feat. Skrillex" ≠ "Korn"; a route
could visit Korn four times. The app's routes use the lead artist; the Lab says so.
